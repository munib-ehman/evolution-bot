An AI agent that finishes in two minutes may still leave twenty minutes of checking and correction. To decide whether the task is worth repeating, measure the whole workflow rather than the time shown in a demo.

You can start with a simple before-and-after worksheet. The aim is not to produce a perfect return-on-investment forecast. It is to find out whether a small trial removes real work without introducing unacceptable errors or hidden effort.

## Record a realistic manual baseline

Time a few normal runs of the original task. Include collecting inputs, doing the work and delivering the result. Note what varies between runs, such as the number of records or the quality of the source material.

Avoid comparing a difficult manual day with an unusually clean automated sample. Use comparable inputs where possible, and write down any differences you cannot control.

## Count the work around the agent

For the trial, record setup time separately from recurring effort. Then measure input preparation, output review, corrections and handling failures. Waiting for a job to finish is also different from actively working on it.

An illustrative worksheet might contain these fields:

| Measure | What to record |
| --- | --- |
| Manual effort | Active minutes per comparable task |
| New recurring effort | Preparation, review and corrections |
| Quality | Missed issues and incorrect changes |
| Reliability | Successful, failed and uncertain runs |
| Cost | Agreed charges and required services |

These are suggested measures, not results from an Evolution customer. Keep unknown costs marked unknown until the provider explains them.

## Keep time savings and quality separate

Subtract new recurring effort from the manual baseline to estimate active time saved per task. Do not count that saving as valuable if the output misses the very issues the task exists to detect.

Check a sample of apparently correct results, not only the exceptions the agent flags. Otherwise a quiet workflow can look efficient because it failed to notice problems. Track additional investigation caused by incorrect flags as well.

## Decide what would justify continuing

Before expanding the task, choose a practical threshold for review effort and acceptable mistakes. A low-risk internal summary can tolerate different imperfections from a workflow that changes live records.

If the trial does not help, simplify the output or reduce the scope before adding more automation. Sometimes the improvement is a better input template rather than a more capable agent. Compare another representative run after the change, and keep the earlier measurements so the decision is grounded in evidence rather than a persuasive demo.
